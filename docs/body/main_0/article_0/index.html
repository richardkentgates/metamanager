What This Package Does

PHP cannot do lossless compression. ExifTool cannot be called safely from PHP in a request path. This package solves both problems by delegating all media work to OS daemons via a filesystem job queue.

The WordPress plugin writes a small JSON job file to wp-content/metamanager-jobs/compress/ or wp-content/metamanager-jobs/meta/. The daemon picks it up via inotifywait and processes it. WordPress never blocks.

Lossless Compression

VideoffmpegContainer remux only. No re-encoding. No quality change. Writes metadata atoms.

Metadata Embedding

The metadata daemon reads and writes embedded tags using ExifTool. It supports bidirectional sync: tags are read on upload and written back after edits in WordPress.

Fields Written

The daemon writes these fields from WordPress into the file's native tag system:

  • Title, Description, Caption, Alt Text
  • Creator, Copyright, Owner, Publisher, Website
  • Headline, Credit, Keywords, Date Created, Rating
  • City, State, Country

GPS coordinates (latitude, longitude, altitude) are read-only — imported from EXIF on upload.

Write-back Verification

After the daemon writes metadata, it re-reads the file to verify the values match WordPress. Discrepancies are recorded in mm_verify_discrepancies post meta and shown on the attachment edit screen.

Daemon Management

metamanager-compress-daemonwp-content/metamanager-jobs/compress/jpegtran, optipng, cwebp, avifenc, ffmpeg

How It Works

  • Event-driven: inotifywait fires on file creation. No polling. No sleep loops.
  • Atomic ownership: First daemon to rename a job file claims it (mv ... .processing).
  • Concurrency: Maximum 4 simultaneous job subshells per daemon.
  • Timeout: 120 seconds per tool invocation.
  • Result files: Written to completed/ or failed/ directory. WP-Cron reads them every 60 seconds.
  • PID files: Stored in wp-content/metamanager-jobs/. Used by plugin for health checks.

Systemd Hardening

Both services run with security hardening: NoNewPrivileges, PrivateTmp, ProtectSystem=strict, ProtectHome, ProtectKernelTunables, ProtectKernelModules, ProtectControlGroups, RestrictSUIDSGID, RestrictNamespaces, LockPersonality, RestrictRealtime, RestrictAddressFamilies, DevicePolicy=closed, UMask=0077.

Commands

# Status
sudo systemctl status metamanager-compress-daemon metamanager-meta-daemon

# Restart (required after plugin updates)
sudo systemctl restart metamanager-compress-daemon metamanager-meta-daemon

# View logs
sudo journalctl -u metamanager-compress-daemon -f
sudo journalctl -u metamanager-meta-daemon -f

Installation

From apt (Debian/Ubuntu)

sudo apt update && sudo apt install metamanager

This installs the daemon scripts, systemd units, and all OS dependencies (jq, inotify-tools, exiftool, jpegtran, optipng, cwebp, ffmpeg, php-imagick).

Updating

Daemon updates are handled by the WordPress plugin's updater. When the plugin updates, it triggers apt-get update && apt-get install -y metamanager. The server's apt channel (test or stable) determines which version is installed.

After updating, the daemons need to be restarted:

sudo systemctl restart metamanager-compress-daemon metamanager-meta-daemon
